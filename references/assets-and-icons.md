# 素材、图标与资源

## 1. 图标：一套体系，粗细统一

> 一整套界面里的图标来自同一个风格体系，线条粗细、圆角、比例、视觉重量要一致。—— [@yanliudreamer](https://x.com/yanliudreamer/status/2113188741452103685)

混用图标库是 AI 界面的隐形杀手：lucide 的 2px 描边配 heroicons 的 1.5px，视觉重量差一倍，放大后才看得出来，缩小后整片区域会显得"糊"。

**规则**
- 一个项目只引入一个图标库（`K001`）。
- 图标尺寸走 16 / 20 / 24 三档，不要 17、22 这种。
- 图标与文字并排时，用 `gap: 6px` + `align-items: center`，不要靠空格。
- 纯图标按钮必须有 `aria-label`。

```jsx
// 对：整套 lucide
import { Camera, MapPin, Search } from 'lucide-react';

// 错：两个库混用，描边粗细对不上
import { Camera } from 'lucide-react';
import { MapPin } from '@heroicons/react/24/outline';
```

**不要用 emoji 当图标。** 它在每个系统上长得不一样，且无法控制粗细、颜色、与文字对齐。

## 2. 图片与插画

- 图片是界面里**允许有颜色**的地方。界面越灰，照片越亮。
- 统一图片的圆角与裁切比例（`aspect-ratio`），不要让每张图自由尺寸。
- 统一色调：一组照片要么都偏冷、要么都偏暖；混着放会显得像随手抓的图库图。
- 没有真实照片时，**不要用 AI 生成的"抽象渐变色块"占位**——那是另一种 slop。用纯色块 + 文字说明更诚实。

## 3. 插画

- 只用一套插画的风格线（粗描边 / 扁平 / 等距，选一种）。
- 插画颜色从品牌色阶里取，不要现调第六种颜色。
- 插画不要和照片混在同一屏同一层级。

## 4. 深色模式与多外观

不同外观的素材要**单独设计**，不能靠滤镜/自动转换。苹果给 Preview 图标的 Clear 模式单独加了一层图（默认模式下不透明度为 0 隐藏），因为直接把默认模式的图转过去"会显得很脏"。[@remixdesigner](https://x.com/remixdesigner/status/2100082157184229741)

落到网页：
- 深色模式重新定 `--line`（黑色描边换成白色低透明度，且更淡）
- 阴影在深色下发灰，改用 `box-shadow: 0 0 0 1px rgba(255,255,255,.06)` 这类"内发光"更自然
- 图片在深色下降低饱和度、加 0.5px 描边，避免亮部糊在背景里
- 不要在深色模式里直接反色（`filter: invert()`），照片会变成负片

## 5. 资源库

[@yanliudreamer](https://x.com/yanliudreamer/status/2113188741452103685) 整理的 10 个工具，按用途归类：

| 用途 | 资源 | 备注 |
|---|---|---|
| 配色 | Coolors | 生成 / 提取色板，注意最终要落到 Radix 色阶 |
| 字体 | Fontshare | 免费商用字体，避开 slop 三件套 |
| 图标 | The Noun Project | 注意风格统一，不要逐个下载混搭 |
| 插画 | Blush | 可选风格线，保持一套 |
| 动效组件 | React Bits | 只取需要的，不要整段复制 |
| 3D | Spline | 谨慎：3D 很容易变成新的 AI 味 |
| 图片 | Unsplash | 统一色调后再用 |
| CTA 文案 | CTA Gallery | 参考真实产品的按钮写法 |
| 品牌规范 | Frontify | 团队协作时定 token |
| AI 交互模式 | The Shape of AI | 做 AI 功能时的交互参考 |

**原则：资源解决的是"起点"，不是"品味"。** 把三个库的东西拼在一起，比从零写更廉价。

## 6. 复用优先

- 项目已有组件库 / 设计系统 / token，就先改 token、复用组件，不要另起一套。
- 参考成熟产品已验证的 UX 模式（设置页、空状态、错误态），不要重新发明。
- 深色模式、RTL、移动端断点，跟着已有系统走。
